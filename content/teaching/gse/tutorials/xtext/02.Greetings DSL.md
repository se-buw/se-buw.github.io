Our second Domain-Specific Language (DSL) is a small extension of the simple language to define greetings. We extend it to allow for greetings with multiple forms, e.g., "Hello" and "Hi", and multiple subjects, e.g., "World" and "Xtext":

```
Hello World!
Hi Xtext and Eclipse!
```

This part introduces enumerations and interfaces as new grammar elements.

We also extend the grammar to support simple repetitions to be defined in greeitings, e.g.,

```
for 5 do
  Hello World and Xtext!
endfor
```

This project overview refers to folder `02.greetingsdsl` in the [code examples repository](https://github.com/se-buw/xtext-intro/tree/main/02.greetingsdsl).

The rule `Element` simply states `Repetition` and `Greeting` as alternative. It is thus an abstract rule that is implemented by the rules `Greeting` and `Repetition`. This allows us to have a list of `Element`s in our model, which can contain both greetings and repetitions.

### Repetitions

Next, we define the rule for repetitions. It starts with the keyword `for`, followed by an integer that specifies how many times the repetition should be executed, followed by the keyword `do`. The body of the repetition is a non-empty list of `Element`s (multiplicity `+`), which can be either greetings or repetitions. Finally, the repetition ends with the keyword `endfor`.

It is important to provide attribute names for the elements of the rule `Repetition`, as these are used in the code generation later on. Without explicit names, the information about the elements is not represented in the meta-model and thus not available when working with the abstract syntax of the model. We use `times=INT` to name the integer attribute that specifies how many times the repetition should be executed, and `elements+=Element+` to name the list of elements that form the body of the repetition. Note the use of `=` for single values and the use of `+=` for lists.

### Greetings

Finally, we define the rule for greetings. A greeting starts with a salutation or form, e.g., "Hello" or "Salut". The form is followed by a list of subjects, e.g., "World" or "Xtext Xtend", and is terminated by an exclamation mark. 

We use a special grammar rule kind of `enum` to define an enumeration of possible greeting forms in rule `GreetingForm`. Each enumeration literal is defined by a name, e.g., `Hello`, and a literal value, e.g., `"Hello"`. The value is the string that is used in the textual syntax of the model, while the name is used in the abstract syntax and in the code generation.

## Code Generation

{{< youtube id="n0jNIAtyarU" >}}

See the [YouTube playlist](https://www.youtube.com/watch?v=n0jNIAtyarU&list=PLGyeoukah9NbZzlK31hTH7oyZ8FRptT29&index=6) for all videos.

We will develop a code generator for our greetings DSL that generates some form of pseudo code for each model. It is easy to change this to generate code in almost any programming language, e.g., Java, Python, or JavaScript. The generated code will be a simple representation of the greetings and repetitions defined in the model. For example, the following model:

```
for 3 do 
	Guten Tag Jan!
endfor
Salut Oliver!
```
will be transformed to the following pseudo code:

```
BEGIN
REPEAT 3 TIMES
	BEGIN 
	SAY "Guten Tag Jan !"
	END
SAY "Salut Oliver !"
END
```

We again use Xtend to implement the code geneator in the existing file `GreetingsGenerator.xtend`. The main method of the generator is `doGenerate`, which is called for each model to be transformed. It takes the root element `resource.contents.head`, which is a `Model` object, and a `fileSystemAccess` object that can be used to write the generated code to a file.

This time we are not using a hard-coded file name for the generated code, but instead we use the name of the model file. We use `resource.URI.lastSegment` to get the last segment of the URI of the resource, which is the name of the model file. We add the additional extension `.txt`: if the filename is `file1.greet` the generated file will be `/src-gen/file1.greet.txt` regardless of the folder that file `file1.greet` is located in.

As before, we use dispatch methods with name `generatePseudoCode` to generate the pseudo code for the different elements of our model (parameters of type `Model`, `Greeting`, and `Repetition`). The first dispatch method is for the root element `Model`, which contains a list of `Element`s as attribute `elems`. We generate the pseudo code for each element in the list by using Xtend's `FOR` loop.

The second dispatch method is for `Greeting` elements. We generate the pseudo code for a greeting by first generating the salutation using the `form` attribute of the greeting, followed by the subjects. As the subjects are stored in a list `subjects`, we use another `FOR` loop over the subjects. However, instead of calling another dispatch method, for each subject we directly generate the pseudo code by printing the name of the subject `«s.name»`. Note the space between `«s.name» «ENDFOR»`. This space belongs to the inside of the loop and is thus printed after each subject, which is important for the correct formatting of the generated code.

Finally, we handle the generation of repetitions in the third dispatch method. We first print the keyword `REPEAT` followed by the number of times the repetition should be executed, which is stored in the attribute `times` of the repetition. Then we print the keyword `BEGIN` to mark the beginning of the body of the repetition. The body is a list of `Element`s stored in attribute `elems`, which we iterate over with a `FOR` loop and generate the pseudo code for each element by calling the dispatch method again. It is important that we use the general dispatch method `generatePseudoCode` for the elements in the body of the repetition, as these can be either `Greeting` or `Repetition` elements. This way we allow for nested repetitions.
Finally, we print the keyword `END` to mark the end of the body of the repetition.

Notice the way we use the tripe quotes `'''` for multi-line string templates in Xtend. This allows us to easily format the generated code with line breaks and indentation. We ensure correct indentation by aligning the code in the next line with the quotes and in all following lines with possible tabs or spaces. This way we can easily generate well-formatted code without having to manually add line breaks and indentation in the generated code. Above this can be seen for the generation of repetitions, where the keywords `REPEAT` is aligned with the quotes in lines 37 and 38, and `BEGIN` is indented with a tab in line 39. 

## Testing the Code Generator

We can try out the code generator by running any of the Xtext projects as an Eclipse application, which will open a new instance of Eclipse with the generated plugins. We  then create a new model file with extension `.greet`, e.g., `file1.greet`, and write some greetings and repetitions in it. On saving the model file, the generated pseudo code will be written to a file with the same name as the model file but with an additional extension `.txt`, e.g., `file1.greet.txt`, in the folder `src-gen` of our project. 

Note that in case the model file is malformed, e.g., if we forget the exclamation mark or misspell a greeting, the editor will show an error and the code generator will delete a previously generated target file rather than generating code with errors.
