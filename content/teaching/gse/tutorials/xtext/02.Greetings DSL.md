Our second Domain-Specific Language (DSL) is a small extension of the simple language to define greetings. We extend it to allow for greetings with multiple forms, e.g., "Hello" and "Hi", and multiple subjects, e.g., "World" and "Xtext":

```
Hello World!
Hi Xtext and Eclipse!
```

This part introduces enumerations and interfaces as new grammar elements.

We also extend the grammar to support simple repetitions to be defined in greeitings, e.g.,

```
for 5 do
  Hello World and Xtext!
endfor
```

This project overview refers to folder `02.greetingsdsl` in the [code examples repository](https://github.com/se-buw/xtext-intro/tree/main/02.greetingsdsl).

The rule `Element` simply states `Repetition` and `Greeting` as alternative. It is thus an abstract rule that is implemented by the rules `Greeting` and `Repetition`. This allows us to have a list of `Element`s in our model, which can contain both greetings and repetitions.

### Repetitions

Next, we define the rule for repetitions. It starts with the keyword `for`, followed by an integer that specifies how many times the repetition should be executed, followed by the keyword `do`. The body of the repetition is a non-empty list of `Element`s (multiplicity `+`), which can be either greetings or repetitions. Finally, the repetition ends with the keyword `endfor`.

It is important to provide attribute names for the elements of the rule `Repetition`, as these are used in the code generation later on. Without explicit names, the information about the elements is not represented in the meta-model and thus not available when working with the abstract syntax of the model. We use `times=INT` to name the integer attribute that specifies how many times the repetition should be executed, and `elements+=Element+` to name the list of elements that form the body of the repetition. Note the use of `=` for single values and the use of `+=` for lists.

### Greetings

Finally, we define the rule for greetings. A greeting starts with a salutation or form, e.g., "Hello" or "Salut". The form is followed by a list of subjects, e.g., "World" or "Xtext Xtend", and is terminated by an exclamation mark. 

We use a special grammar rule kind of `enum` to define an enumeration of possible greeting forms in rule `GreetingForm`. Each enumeration literal is defined by a name, e.g., `Hello`, and a literal value, e.g., `"Hello"`. The value is the string that is used in the textual syntax of the model, while the name is used in the abstract syntax and in the code generation.

## Code Generation

{{< youtube id="n0jNIAtyarU" >}}

See the [YouTube playlist](https://www.youtube.com/watch?v=n0jNIAtyarU&list=PLGyeoukah9NbZzlK31hTH7oyZ8FRptT29&index=6) for all videos.

We will develop a code generator for our greetings DSL that generates some form of pseudo code for each model. It is easy to change this to generate code in almost any programming language, e.g., Java, Python, or JavaScript. The generated code will be a simple representation of the greetings and repetitions defined in the model. For example, the model

```
for 3 do 
	Guten Tag Jan!
endfor
Salut Oliver!
```
will be transformed to the following pseudo code:

```
 BEGIN
REPEAT 3 TIMES
	BEGIN 
	SAY "Guten Tag Jan !"
	END
SAY "Salut Oliver !"
END
```

We again use Xtend to implement the code geneator in the existing file `GreetingsGenerator.xtend`. The main method of the generator is `doGenerate`, which is called for each model to be transformed. It takes the root element `resource.contents.head`, which is a `Model` object, and a `fileSystemAccess` object that can be used to write the generated code to a file.
