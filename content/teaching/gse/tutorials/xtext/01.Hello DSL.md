## Creating an Xtext Project and Grammar

{{< youtube id="2nIe0IElS6A" >}}

See the [YouTube playlist](https://www.youtube.com/watch?v=2nIe0IElS6A&list=PLGyeoukah9NbZzlK31hTH7oyZ8FRptT29&index=2) for all videos.

To create an Xtext DSL we need to start by creating an Xtext project in Eclipse. It turns out that for the most common cases we obtain five rather than a single project all created by the project wizard. 

We select `File > New > Project... > Xtext > Xtext Project` and then follow the steps in the wizard. The first step is to select a `Project name` for the project. This name will appear in the project names and generated Java packages. We will use `org.xtext.example.hellodsl` as the project name. The second step is to select a `Language name` for the DSL qualified by the project name. We will use `org.xtext.example.hellodsl.HelloDsl` as the language name. The third step is to select a `File extension` for files written in the DSL. We will use `hello` as the file extension.

Next, we keep the default values selecte for all ohter steps and click `Finish`. This creates the following projects in the workspace:
- `org.xtext.example.hellodsl`: the main project containing the grammar and code for code generation
- `org.xtext.example.hellodsl.ide`: the project containing generic IDE code not tied to Eclipse
- `org.xtext.example.hellodsl.tests`: the project containing code for testing the DSL
- `org.xtext.example.hellodsl.ui`: the project containing the UI components of the DSL editor for Eclipse
- `org.xtext.example.hellodsl.ui.tests`: the project containing tests for the UI parts

The grammar of the DSL is defined in the file `src/org/xtext/example/hellodsl/HelloDsl.xtext` in the main project `org.xtext.example.hellodsl`. The grammar defines the structure of models written in the DSL and also serves as a basis for generating an editor for the DSL. The grammar consists of rules defining how to write models in the DSL. The main rule is `Model` which defines that a model consists of zero or more `Greeting` elements. A `Greeting` consists of the keyword `Hello` followed by a name (an identifier of type `ID`) and an exclamation mark as shown below:

### Generating Language Artifacts
Before using or testing the DSL, we need to generate its parser, abstract syntax tree (AST) metamodel, and the editor infrastructure:
1. Locate the `GenerateHelloDsl.mwe2` script in the same project's `org.xtext.example.hellodsl` source folder (next to the grammar file).
2. Right-click the file and select `Run As > MWE2 Workflow`.
3. Wait for the generation process to complete (you will see it downloading ANTLR dependencies and logging progress in the console).

Note that this generation step needs to be repeated whenever you make changes to the grammar. It will change files across multiple projects, including the generated parser and editor code.

### Unit Testing the Parser

To see what kind of models can be parsed by the generated parser, we can write unit tests.

The Xtext wizard automatically generated a `.tests` project to place our test cases and verify our parser. 
1. Open `HelloDslParsingTest` in the `org.xtext.example.hellodsl.tests` project.
2. Run it by right-clicking the file and selecting `Run As > JUnit Test`. 
3. You can optionally add multiple negative and positive tests here (e.g., verifying that omitting the `!` correctly triggers parsing errors by checking that the `errors` list is not empty).

### Running the Eclipse Editor UI
To experience the IDE syntax highlighting and code completion generated by Xtext:
1. Right-click the main project `org.xtext.example.hellodsl` and select `Run As > Eclipse Application`.
2. A new, nested Eclipse instance will start up.
3. In this new instance, select `File > New > Project... > General > Project` and create a project named `hello-project`. You could use any kind of project or project name, but a simple general project is sufficient for our purposes.
4. Inside `hello-project`, create a new file named `file1.hello`. The important bit is the file extension `.hello` which is associated with our DSL. You can do this by right-clicking the project, selecting `New > File`, and then entering `file1.hello` as the file name in the dialog that appears. Click `Finish` to create the file.
5. You will be prompted to add the "Xtext nature" to your project (as it now creates a file recognized by an Xtext editor). Click **Yes**.
6. Open the file and start typing. You can press `Ctrl + Space` to trigger autocompletion, demonstrating the DSL's tooling in real time.

## Abstract-Syntax and Meta-Model Inspection as Class Diagram

{{< youtube id="yQy6V3S1Y4o" >}}

See the [YouTube playlist](https://www.youtube.com/watch?v=yQy6V3S1Y4o&list=PLGyeoukah9NbZzlK31hTH7oyZ8FRptT29&index=4) for all videos.

To understand the structure of the models we are working with, it is useful to inspect the abstract syntax and meta-model of our DSL as a class diagram. The abstract syntax defines the structure of models in terms of classes and their relationships. The meta-model is a more representation of the abstract syntax used by Xtext for parsing and code generation.

Eclipse Ecore can create a class diagram from the Ecore meta-model generated by Xtext. To do this, we need to locate the Ecore file generated by Xtext for our DSL. This file is located in the `model/generated` folder of the main project `org.xtext.example.hellodsl` and is named `HelloDsl.ecore`. 

The creation of class diagrams requires the installation of the `Ecore Diagram Editor`. You can install it by going to `Help > Install New Software...`, selecting `Ecore Diagram Editor`, and installing the plugin from there (check the video for the steps). After installing the plugin, you may need to restart Eclipse.

We can right-click the `HelloDsl.ecore` file and select `Initialize Ecore Diagram` to create a class diagram from the Ecore meta-model. This will open a wizard and later a new editor for the class diagram. Follow the steps in the video to visualize the class diagram.
