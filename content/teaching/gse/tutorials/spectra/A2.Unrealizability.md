In this module, you analyze unrealizability, unrealizable cores, and counter-strategies.

## What you learn

- How to localize unrealizability using minimal cores.
- How counter-strategies explain environment behavior that defeats every system strategy.
- How to choose the right analysis tool depending on the kind of failure.

## How to work through this page

1. Reproduce unrealizability with `Check Realizability`.
2. Compute a core and inspect whether it already explains the issue.
3. If needed, generate a counter-strategy and trace the environment choices.

Use this workflow when a specification is unrealizable:

1. Run `Check Realizability`.
2. Compute an unrealizable core (`Spectra Add-ons -> Cores -> Find Unrealizable Core`).
3. If the core is not informative (for example, core size 1 without obvious contradiction), generate a concrete counter-strategy.

A core identifies a minimal subset of guarantees that is already unrealizable. A counter-strategy shows how the environment can force failure.

Rule of thumb:

- If the core shows an obvious contradiction, start there.
- If the core is too small or too large to explain behavior, use a counter-strategy.

Typical reasons seen in the solution cases:

- Missing assumptions: the environment can keep cars absent forever, so some liveness guarantees can never be met.
- Over-constrained guarantees: one lane effectively requires green always while mutual exclusion forbids satisfying another liveness goal.
- Deadlock-style violation: inputs can force a state where every possible system response violates some safety guarantee.
