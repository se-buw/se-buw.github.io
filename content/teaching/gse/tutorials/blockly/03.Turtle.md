This project overview refers to folder `03.turtle` in the [code examples repository](https://github.com/se-buw/blockly-intro).

In this project, we build a small turtle graphics language with movement and turning commands, loops, and simple routines. The major difference compared to the previous examples is code generation: instead of defining a generator from scratch, we reuse Blockly's JavaScript generator and extend it with custom generation rules for our own blocks.

The executable example is available as <a href="../dist/03.turtle" target="_blank">turtle language</a>.

This block deserves special attention. Its dropdown options are computed dynamically from all `routine_def` blocks currently in the workspace (lines 65-79). Every time Blockly renders the dropdown, function `dropdownOptions` collects routine names from the current model and rebuilds the list.

This is similar in spirit to a scope provider: users can only choose valid routine names that currently exist. Here, the translation is not one-to-one string replacement; semantic decisions are made:
1. Blockly concept "move backward by x" is translated to numeric sign inversion `-(x)`.
2. Blockly concept "turn left by a" is translated to a negative angle.
3. Blockly value inputs are translated via `valueToCode(...)`, so connected expression blocks (not just literals) can contribute JavaScript expressions.
4. Missing inputs are translated to safe defaults (`0` or `90`) via `getNumberInput(...)`.

Conceptually, a visual `routine_def` block becomes a JavaScript `function`. The block name (`ROUTINE_NAME`) becomes the function name, while the nested statement input `BODY` becomes the function body. The generated function is added to `definitions_`, which lets Blockly place definitions in the generated program in a consistent way.

This translation includes a validation step: if no valid routine is selected (`NONE` or empty), the generator emits no code. Otherwise, the selected routine name is translated to `routineName();`.

Overall, the generator performs a model-to-text translation from Blockly concepts (direction, angle, routine body, routine reference) to executable JavaScript that targets a small turtle runtime API.

## Simulation overview

The simulator is implemented in `src/simulator.ts` and follows a small command-based architecture.

Generated JavaScript does not draw directly. Instead, it calls a turtle API with two operations (`move` and `turn`). The simulator records these operations as commands and executes them as an animation sequence on the canvas.

The execution flow is as follows:
1. Reset simulator state (position, heading, and path).
2. Execute generated JavaScript against the turtle API.
3. Animate the queued commands step by step.

This separation is useful because we can change visualization details (animation speed, rendering, sprite) without changing block definitions or generator rules.

## Testing the generator

Testing is mostly analogous to the previous example and is implemented in `src/generator.test.ts` using [Vitest](https://vitest.dev/). The tests mainly verify that custom turtle blocks generate the expected JavaScript and that built-in Blockly blocks (such as `controls_repeat_ext`) integrate correctly with our generator extensions.
