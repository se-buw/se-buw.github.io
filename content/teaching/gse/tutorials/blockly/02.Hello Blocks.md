This project overview refers to folder `02.helloBlocks` in the [code examples repository](https://github.com/se-buw/blockly-intro).

In this project, we slightly extend the previous example of the `greeting` block. We change the input fields to be input values. This allows us to define the values in terms of other blocks, which can be connected to the input fields. We add a block for text and one for numbers from the blockly library.

The executable example is available as <a href="../dist/02.helloBlocks" target="_blank">hello blocks language</a>.

The main change is in the definition of the input fields in lines 10-19. Instead of defining fields, we now define value inputs (type `input_value`) with names `TIMES` and `SUBJECT`. We add `check` attributes to specify the types of blocks that can be connected to these inputs. For the `TIMES` input, we specify that only blocks producing `Number` can be connected. For the `SUBJECT` input, we specify that only blocks of type `text` can be connected.

A straight forward change it so adapt the name of the block type in the function `generator.forBlock()` from `greeting` to `greeting_external` (line 14).

However, The main change is in the way we access the input values. Instead of using `getFieldValue()` to access the values of fields, we now use `valueToCode()` to access code generated for the values of input fields. This function takes three parameters: the first parameter is the name of the block, the second parameter is the name of the input field, and the third parameter is an operator precedence level (we simply use `0` in lines 15 and 16), which is used to determine whether parentheses are needed around the generated code for this input.

As our custom code generator does now know how to generate code for `text` and `math_number` blocks, we need to add additional code generation logic for these blocks. This is done in lines 26-35. Again, we use opeator precedence level `0` (in lines 29 and 34) for the generated code of these blocks, which means that the generated code will not be wrapped in parentheses.
