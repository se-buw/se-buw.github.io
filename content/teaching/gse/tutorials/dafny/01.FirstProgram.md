Note that we have to first assign the return value of the call `GetHelloWorld("en")` to a new variable `text` in line 13 before we can print it in the `Main` method. This is because Dafny does not allow to use a method call directly in an expression.

You will find that [this extended program](https://play.formal-methods.net/?check=DFY&p=diner-cement-prune-oil) fails to run. The error message produced tells us that the element `langCode` in line 9 may not be present in the domain of the map `greetings`. While other programming languages would simply try and potentially throw an exception at runtime, Dafny is a verification-aware programming language and thus requires us to prove that the program is correct. In this case, we need to ensure Dafny that the element `langCode` for the lookup in line 9 is  present in the domain of the map `greetings`.

## Verification-aware programming

Dafny is a verification-aware programming language. It automatically attempts to verify some correctness properties of programs. These include the absence of runtime errors, e.g., invalid lookups in maps. We can tell Dafny that it may assume that whenever the method `GetHelloWorld` is called, the argument `langCode` is within the set `{"en", "es", "fr"}`. ## Ensuring Properties

So far, we have seen Dafny as a programming language that ensures some general correctness properties of programs, e.g., the absence of runtime errors. However, we can also use Dafny to ensure stronger and more specific properties of the programs we are developing. For example, we can ensure that the method `GetHelloWorld` never returns an empty string. We do so by adding a postcondition with the keyword `ensures` to the method `GetHelloWorld` in line 3:

This postcondition is satisfied [by our current implementation](https://play.formal-methods.net/?check=DFY&p=elves-bagel-hybrid-lying) of `GetHelloWorld` which always returns a non-empty stringfor a `langCode` in `{"en", "es", "fr", "de"}`.

We may want to ask for an even stronger property, e.g., that the returned `greeting` string always ends with an exclamation mark. We can express this property as a postcondition in line 4:

{{< sub-code 
  file="code-examples/dafny-intro/01.helloLanguages/08.HelloWorld_missingExclamation.dfy" 
  lang="dafny" 
  linenos="true"
  hl_lines="2 4 11 18"
>}}

The [updated program runs](https://play.formal-methods.net/?check=DFY&p=pulp-wilder-parish-wound) successfully. But wait, isn't there an entry in the map on line 11 that does not end with an exclamation mark? Indeed, the entry for `"de-ch"` is `"Grützi"` which does not end with an exclamation mark. Dafny is able to verify that this postcondition is satisfied because it can see that the entry for `"de-ch"` in line 11 is never returned by the method `GetHelloWorld` as the precondition in line 2 does not allow to call the method with `langCode == "de-ch"` as argument. If we try to call the method `GetHelloWorld` with `"de-ch"` as argument in line 18, Dafny will again prevent us from running the program as the precondition in line 2 is violated. 

Updating the precondition in line 2 to include `"de-ch"` in the set will finally lead to a verification error in line 4 as the postcondition is violated by the entry for `"de-ch"` in line 11.
